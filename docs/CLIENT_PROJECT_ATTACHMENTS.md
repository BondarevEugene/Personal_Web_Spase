# OMNIFACTORY — приватные вложения клиентских проектов

Этот этап добавляет загрузку и скачивание небольших вложений в `/account/projects/{id}` и `/support/projects/{id}`.

## Технический контракт
- Содержимое сохраняется транзакционно в **закрытой таблице портала** (PostgreSQL/Neon или SQLite в разработке). Никаких публичных static-URL и временных файлов на Railway.
- Форматы: PDF, PNG, JPEG, UTF-8 TXT. Сервер ограничивает чтение **2 МиБ на файл**, проверяет расширение и основные сигнатуры содержимого; `content-type` браузера не считается доверенным.
- До **8 вложений / 8 МиБ** на проект. Новая загрузка под тем же именем создаёт новый номер версии без стирания старой.
- Для каждой версии фиксируются загрузивший пользователь, время, длина в байтах, SHA-256 и содержимое.
- Скачивание доступно только участникам организации заказа и операторам, явно включённым в `OMNI_SUPPORT_OPERATOR_IDS`; всегда `Content-Disposition: attachment`, `no-store`, `nosniff`.
- Создание файла требует действующую сессию и CSRF; для закрытого/отменённого заказа новые загрузки запрещены. Операции записываются в журнал проекта и личный inbox.
- Нет обновления или удаления старых версий пользователем.

## Существенные ограничения безопасности и стоимости
- **Это ограниченное хранилище в базе**, не облачный объектный storage и не полноценная медиа-библиотека. Лимит сделан низким, чтобы не расходовать дорогой объём Neon. Для массовых и больших файлов потребуется private object storage с квотами и expiring download URL.
- Базовая проверка сигнатур **не заменяет антивирус, санитизацию PDF/изображений и проверку архива**. Не следует увеличивать лимиты или принимать пользовательские ZIP/DOCX/EXE до подключения сканера файлов и дополнительной защиты при приёме multipart.
- Web-сервер разбирает multipart до вызова обработчика. На публичном развёртывании необходимо дополнительное ограничение **полного размера HTTP-body на reverse proxy / ingress**.
- Подтверждение редакции ТЗ из PR #55 относится к **текстовым документам**, а не к загруженным бинарным файлам. Вложение само по себе не становится согласованным юридически значимым документом.

## Приёмочные проверки
```powershell
.\.venv-omni\Scripts\python.exe -m ruff check .
.\.venv-omni\Scripts\python.exe -m pytest -q tests/test_client_project_attachments.py
.\.venv-omni\Scripts\python.exe -m pytest -q
.\.venv-omni\Scripts\python.exe -m alembic -c portal_alembic.ini upgrade head
```

Миграция `20261119_portal_15` должна выполняться **после** `_14`, через прямой Neon URL, не через pooler. Проверьте открытие файла под клиентом и оператором, 404 под другой организацией, попытки загрузки скрытого исполняемого файла и превышения квот. После создания публичного ingress настройте общий body-size limit.

## Дальнейшие шаги

- Привязка вложений к конкретным версиям согласуемого ТЗ и предоставление артефактов сдачи в приёмке.
