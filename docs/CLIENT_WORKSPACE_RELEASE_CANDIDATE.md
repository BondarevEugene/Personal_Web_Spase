# OMNIFACTORY Client Workspace — Release Candidate: customer acceptance

## Цель релизного шлюза

Клиент и оператор должны завершить реальный бизнес-процесс, а не просто
переключить красивый статус: **заказ → план → разработка → приёмка →
мотивированная доработка → повторная сдача → приёмка клиентом**.

## Новое поведение

- Только **владелец организации**, которой принадлежит заказ, может вернуть
  проект со статуса `review` на `in_progress`.
- Кнопка возврата требует конкретный комментарий от **15 до 2000 символов**.
  Комментарий сохраняется в журнале проекта с типом `revision_requested`,
  фиксируется изменение статуса и создаётся внутреннее уведомление участникам
  этой организации.
- Оператор видит реальный журнал и может возвратить уже завершённый этап в
  работу, исправить результат, снова завершить его и отправить на приёмку.
- Если после возврата клиент повторно нажимает старую кнопку, сервер
  отвечает `409`. Другая организация получает `404`, не раскрывая проект.
- Принятие результата по-прежнему требует завершённых этапов и
  согласованной последней редакции текстового технического задания.
- Сервер применяет блокировку записи при смене статуса, возврате на
  доработку и окончательном принятии: при PostgreSQL два конкурирующих
  запроса не должны одновременно менять статус одного проекта.
- Существующие документы, вложения, уведомления, счета и редактор Graph
  Studio не изменяются.

## Регрессионные проверки

```powershell
.\.venv-omni\Scripts\python.exe -m ruff check .
.\.venv-omni\Scripts\python.exe -m pytest -q tests/test_client_workspace_release_candidate.py tests/test_client_project_lifecycle.py tests/test_client_project_attachments.py tests/test_client_workspace_i18n.py tests/test_client_finance_center.py tests/test_account_security_center.py
.\.venv-omni\Scripts\python.exe -m pytest -q
```

В браузере клиента: отправить новый заказ, просмотреть документы и файлы,
запросить доработку с комментарием, обновить страницу, проверить журнал.
В интерфейсе оператора: увидеть замечание, переоткрыть этап, исправить и
повторно отправить на приёмку. Под другим аккаунтом: не видеть и не
изменять заказ. На телефоне: проверить форму комментария и кнопки.

## Ограничения / GO–NO-GO

CI должен быть зелёным. Следующий отдельный эксплуатационный gate —
конфигурация Neon, секреты, реальный HTTPS, объектное хранилище и полная
проверка мобильных браузеров на целевом хосте. Этот релиз не добавляет
электронную подпись, платежи или автоматическую публикацию Telegram-ботов.
Новых миграций нет: используются уже существующие модели проекта,
аудита, уведомлений и этапов.
