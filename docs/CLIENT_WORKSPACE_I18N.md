# OMNIFACTORY — локализация рабочего кабинета UA / RU / EN

## Целостный пользовательский сценарий

1. Клиент входит в свой личный кабинет.
2. Во всех основных рабочих разделах доступна компактная переключалка `UA / RU / EN`.
3. Переключение — POST `/account/language` с сессионной авторизацией и защитой CSRF; язык сохраняется в существующих `CustomerSettings.language`.
4. Сервер при рендеринге получает настройку и передаёт `ui_lang` + функцию `t(source)`. В результате атрибут `<html lang>` и переведённые заголовки/навигация синхронны без клиентского JS.
5. Два клиента не делят настройки языка и не могут изменить настройки другого.
6. Локализованы основные пользовательские надписи на `/account`, `/account/projects`, деталях заказов, `/account/notifications`, `/account/finance`, `/account/billing`, `/account/tickets` и карточке обращения.

## Технические границы

- Русские исходные строки используются как ключи. Если перевод отсутствует, интерфейс оставляет исходный текст; новые тексты необходимо добавлять в `portal/i18n.py`.
- Названия клиентских проектов, сообщения и содержимое документов **не переводятся автоматически**: это первичные пользовательские данные.
- Тарифные цены, статусы платежей в БД, определения сценариев, CSRF и права доступа не зависят от языка.
- Ключевые пользовательские разделы локализованы, но **операторские экраны, вход/регистрация, часть длинных метаданных, уведомления, сформированные ранее, и ошибки backend пока не покрыты полностью**. Не объявлять полную локализацию всей платформы или юридических документов.

## Приёмка

```powershell
.\.venv-omni\Scripts\python.exe -m ruff check .
.\.venv-omni\Scripts\python.exe -m pytest -q tests/test_client_workspace_i18n.py tests/test_client_workspace_unified.py
.\.venv-omni\Scripts\python.exe -m pytest -q
```

Проверить переключение на телефоне в каждом из восьми экранов, после обновления страницы и при повторном входе. Войти под вторым аккаунтом — язык должен оставаться независимым. Создать проект на UA, прочитать на EN: содержание пользовательского задания не меняется, переводятся только системные подписи.

Новых миграций и платёжных интеграций в этом PR нет.
